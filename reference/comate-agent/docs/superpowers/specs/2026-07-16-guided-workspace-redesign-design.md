# 引导式招聘工作台视觉重设计

## 目标

把第一期“职位创建与 Agent 澄清”重设计为更专业、克制、可持续扩展的招聘工作台。视觉基线改为用户提供的角色澄清截图：浅色导航轨、中间 Agent 对话与选项卡、右侧实时搜索标准。

本次只调整视觉语言、排版和页面结构；保留已实现的原生 GET 表单、职位澄清状态机、localStorage 保存、审计记录和全部本地模拟安全边界。

## 设计原则

- **招聘任务优先：** 中间主列由 Agent 提问驱动。每轮只给一个清晰问题和有限选项，让雇主逐步收缩岗位要求，而非填写一张长表单。
- **信息可核对：** 右列始终显示结构化职位摘要与完成状态，帮助招聘负责人判断当前输入是否准确。
- **严格排版：** 中文正文为 14–15px、行高 1.6；问题标题为 28–32px、行高 1.25；导航与标签 12–13px。全页只使用 Geist Sans 与 Geist Mono。
- **低噪声层级：** 用留白、细分隔线和浅表面色区分区域；只用深紫作为主操作与当前步骤状态，薄荷绿只用于安全/完成提示。
- **对话可回顾：** 已确认回答压缩为“Q / A”对话气泡与一句 Agent 追问过渡；当前问题位于页面视觉焦点，选项使用单选/多选列表。

## 页面结构

### 1. 新建职位入口 `/hire`

- 左侧 224px 导航轨：品牌、当前工作区、底部本地模式说明。
- 主列宽度控制在 680px：16px 标题、32px 页面标题、14px 说明、无阴影的文档式文本域。
- 右侧 280px 帮助列：三条职位描述提示和本地模拟说明。
- 主按钮使用深紫实色；示例职位改为紧凑的文字链接或浅描边条目，避免单独大卡片。

### 2. 职位澄清工作台 `/hire/role/[roleId]`

- **左列：** 224px 固定导航，当前职位名为单行文本，避免大面积灰底。
- **中列：** 顶部保留职位原始描述的浅灰对话气泡；随后按时间纵向显示已回答的 `Q / A` 气泡与 Agent 过渡语。页面底部固定当前问题卡：问题标题、可选进度、单选/多选列表、自定义补充输入、跳过和下一步。每次提交后当前问题变为回顾气泡，下一个问题自然接续。
- **右列：** 上半部分显示“进展”纵向步骤，下半部分显示“搜索标准”。搜索标准将角色、地点、资历、必备能力和排除条件即时变成紧凑标签或文本清单；未填写字段不抢占注意力。
- **确认态：** 中列切换为紧凑 Brief 审核清单，右列保持最终摘要。确认按钮仍只确认本地模拟搜索条件。

## 字体与令牌

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--rh-ink` | `#1E1E24` | 标题、主要正文 |
| `--rh-muted` | `#77737D` | 次要说明、未完成字段 |
| `--rh-canvas` | `#FCFBF8` | 主画布 |
| `--rh-rail` | `#F4F2EC` | 左导航与弱表面 |
| `--rh-line` | `#E7E3DC` | 分隔线、输入框 |
| `--rh-primary` | `#4F36B8` | 主操作、当前步骤 |
| `--rh-success` | `#E7F6EC` | 本地安全/完成提示底色 |

字体：`Geist Sans` 用于中文 UI，字重限定为 400 / 500 / 600 / 700；`Geist Mono` 只用于短状态或计数。问题标题为 20–24px，正文 14–15px，气泡内文本 14px。禁止超 32px 的页面标题和大面积字距压缩。

## 组件与实现边界

- 新建 `RecruitingWorkspaceShell`、`ClarificationTranscript`、`CurrentQuestionCard`、`SearchCriteriaPanel`、`ProgressRail`、`LocalModeNotice` 等纯展示组件；领域状态、仓储和原生表单字段不改语义。
- 重构现有 `RoleSidebar`、`WorkflowStepper`、`AgentConversation`、`SearchCriteriaPanel`、`BriefReview` 的 class 与布局；保留输入 name、GET action、hidden command fields 和路由参数。现有选项动作继续用原生表单提交，保证在内置浏览器中可推进。
- 图标只使用项目中已安装并与目标一致的线性图标库；不使用 emoji、CSS 图形、手写 SVG、渐变球或临时插画。
- 保持桌面优先，并在 900px/680px 将右列下移、导航收起；正文、主按钮和表单控件不得横向溢出。

## 验收标准

1. `/hire` 与职位工作台在 1440px 宽度下有明确的 224px / 主列 / 320px 三栏比例，文本区域不拥挤。
2. 任一页面不出现大于 32px 的标题、渐变装饰球、emoji 或无功能装饰卡片。
3. 标题、正文、标签和辅助信息可仅凭字号、字重、色彩和间距区分；正文不少于 14px。
4. 每个已回答问题以 Q / A 气泡回顾；当前问题显示选项、进度和自定义补充输入，右侧搜索标准在回答后即时更新。
5. 已验证的原生表单操作仍可推进：新建职位、地点选择、下一问、跳过、返回与 Brief 确认。
6. 匿名公司、全程本地模拟和“不会触发真实招聘行为”的提示仍可见。
7. `npm run test`、`npm run typecheck`、`npm run lint`、`npm run build` 通过；浏览器中核验入口与至少一个澄清选项。

## 非范围

- 不改变招聘问题、领域模型、持久化格式和路由结构。
- 不引入真实候选人、发布、邀约、支付、认证或第三方服务。
- 不复制 Metix 的商标、logo、专有内容或候选人资料。
