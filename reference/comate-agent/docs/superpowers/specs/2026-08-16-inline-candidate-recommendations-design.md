# 职位确认后的内嵌候选人推荐

## 目标

用户在职位澄清页面点击职位摘要卡的“确认”后，不离开当前交互流程页面。确认成功后，在职位摘要卡下方展示一张横向候选人推荐卡片；只有点击“全部简历”或单个候选人的“查看简历”时才进入简历筛选页面。

## 交互流程

1. 用户点击 `RoleBriefSummaryCard` 的“确认”。
2. 客户端调用现有职位确认接口，按钮在提交期间保持禁用状态。
3. 确认成功后，当前 URL 与当前页面视图保持不变。
4. 当前对话流底部淡入 `CandidateRecommendationStage`。
5. “全部简历”跳转至 `/hire/role/[roleId]?view=screening&mode=all`。
6. “查看简历”跳转至 `/hire/role/[roleId]?view=screening&mode=all&candidate=[candidateId]`。
7. “换一批候选人”在当前推荐卡内切换到下一组本地虚构候选人，不触发路由跳转。

确认失败时保留当前页面与摘要卡，使用现有错误区域展示原因，不显示推荐卡。

## 视觉设计

推荐区严格参照用户提供的设计图：

- 外层为白色、轻描边、圆角的横向大卡片，与当前浅色招聘工作台保持一致。
- 顶部左侧显示“推荐候选人”和一行说明，右侧为“全部简历”次级按钮。
- 主体固定展示三张等宽候选人卡，桌面端横向排列。
- 每张候选人卡包含匿名柔焦头像、姓名缩写、职位、城市与经验、匹配度、三条匹配优势和底部“查看简历”按钮。
- 匹配度、列表圆点和链接使用现有品牌蓝色；边框、阴影保持轻量。
- 底部居中显示“换一批候选人”及刷新图标。
- 推荐区使用 180–260ms 的透明度与纵向位移动画进入，并支持 `prefers-reduced-motion`。
- 900px 以下改为单列排列，所有按钮保持至少 44px 的可点击高度。

## 插图资产

生成三张统一风格的匿名职业头像：

- 柔焦、低辨识度、自然办公环境；
- 分别呈现不同人物轮廓与服装色彩；
- 方形构图，在 UI 中裁切为圆形；
- 不包含文字、品牌标识或真实人物身份特征；
- 保存到 `public/assets/recruiting/`，由 Next.js `Image` 组件加载并声明尺寸。

## 组件与状态

### `RoleBriefWorkspace`

- `handleConfirm` 仅执行确认，不再调用 `router.replace`。
- 确认成功后依赖更新后的 `role.lifecycleState === "confirmed"` 渲染当前创建视图。
- 直接通过 URL 进入 `view=screening` 时，继续保留现有推荐页与全量筛选页逻辑。

### `AgentConversation`

- 在职位摘要卡后，根据 `role.lifecycleState === "confirmed"` 内嵌候选推荐组件。
- 接收 `roleId`，确保推荐区可以构造筛选页面链接。

### `CandidateRecommendationStage`

- 增加适合内嵌场景的样式修饰参数，避免独立页面的全视口最小高度。
- 从本地 `seedCandidates` 生成三人一组的候选数据。
- 使用组件本地批次状态实现“换一批候选人”。
- 保持独立 `view=screening` 页面兼容。

## 数据与隐私

候选信息全部来自本地虚构种子数据。推荐卡默认使用匿名姓名缩写和生成式头像，不展示真实联系方式。匹配度与匹配优势仅用于原型展示。

## 测试

- 更新职位工作台交互测试：确认成功后不切换 URL，并显示推荐候选人区。
- 新增推荐组件测试：展示三张卡、“全部简历”链接正确、“查看简历”携带候选人 ID、“换一批”替换内容。
- 运行相关 Vitest 测试、TypeScript 检查和 ESLint。
- 手动验证桌面横排、900px 以下单列、键盘焦点及减少动画设置。

## 范围外

- 不实现真实候选人检索或推荐算法。
- 不改造全量简历筛选页面的信息架构。
- 不新增外部图片服务或运行时图片请求。
