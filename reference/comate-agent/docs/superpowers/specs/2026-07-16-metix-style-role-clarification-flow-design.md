# Metix 风格职位澄清流程重做设计

## 目标

将当前第一期招聘工作台改为一条连续、全屏的职位创建与 Agent 澄清流程。视觉结构以用户最新提供的四张参考截图为准：Metix 的首页输入体验、底部选项问答、纵向 Q/A 历史与右侧条件收缩；品牌、中文文案、模拟数据和安全边界使用 Nexus Hire 自有实现。

这是一次对已有界面结构的重做，不改变现有的本地角色状态机、原生 GET 表单协议、localStorage、审计记录或“禁止真实招聘副作用”的边界。

## 信息架构

### A. 首页 `/hire`

- **左栏（236px，整屏固定）**：Nexus Hire 文字品牌、`新建职位`、`职位简报`、`面试`、角色列表；底部为纯本地模拟标记和招聘负责人入口。没有空白右栏，也没有单独的帮助栏。
- **主区（占据侧栏以外的全部宽度）**：居中显示一个简洁的 Agent 标记、欢迎语、简短价值说明和职位描述输入器。内容视觉中心位于视口中部偏下。
- **输入器**：约 880px 宽、上方为可输入的多行职位描述，底部为本地辅助入口的静态提示和右侧提交按钮。首版只启用文字描述；“文件/链接”入口标记为本地模拟，不上传、抓取或请求外部内容。
- **提交**：输入不少于 16 个字符后创建本地角色草稿并进入 `/hire/role/[roleId]`。

### B. 角色澄清 `/hire/role/[roleId]`

- **整体布局**：`rolebrief-shell` 为完整视口的 Flex 容器；左栏固定 236px，`rh-main` 必须 `flex: 1` 且 `min-width: 0`，杜绝截图中工作台在中间提前结束、右侧大片留白的问题。
- **顶部**：主区显示职位标题；已回答较少时不展示多余的全局顶栏文案。右侧可保留非功能的本地状态文字，但不能挤压工作区。
- **中列**：以可滚动的时间线显示原始职位描述、已有 Q/A 气泡和一条简短的 Agent 收缩语。第一次提问时，原始需求位于上方，当前问题卡位于主列下半部；后续问题向下接续，用户可回顾历史。
- **当前问题卡**：固定宽度 720px、白色细边框；问题标题、单选/多选圆点列表、自定义输入与提交按钮全部处于同一张卡中。单选项按顺序展示编号；多选使用复选框；非必填问题可跳过。
- **右栏（约 320px）**：与中列等高并贴在浏览器右边缘。上方是纵向“进度”，下方是“搜索标准”。每回答一题，相关字段从“待补充”变成结构化标签或单行内容，同时增加 `criteriaVersion`。

### C. 收缩逻辑

1. 用户写入职位描述：仅抽取本地标题，不触发真实岗位发布。
2. Agent 先问地点；地点作为必填项写入 `RoleBrief.location`。
3. 每次答案由现有 `answerQuestion` 进入领域状态并生成 `AnswerRecord`。
4. 展示层从 `RoleBrief.answers` 生成 Q/A 历史；当前问题从 `getActiveQuestion` 得出。
5. `SearchCriteriaPanel` 仅从 RoleBrief 的已确认字段派生条件版本和标签，不持有另一份业务状态。
6. 完成全部澄清后进入本地 Brief 审核；确认只写入本地审计状态，不搜索、筛选、邀约或联系任何真实候选人。

## 视觉令牌与排版

- 使用暖白主画布、浅灰侧栏、细灰分隔线、深灰文字和单一紫色作为活动状态；没有渐变球、彩色大卡片或装饰性右栏。
- 左栏为 236px；右栏为 320px；中列使用剩余宽度，内容最大宽度 900px；当前问题卡最大宽度 720px。
- 首页欢迎标题 32–36px；工作台职位标题 26–30px；当前问题标题 22–24px；正文 14–16px；辅助标签 11–13px。
- 视觉焦点顺序：当前问题 > 历史 Q/A > 右侧条件 > 左栏导航。
- 图标保持单一线性图标库；不用 Metix Logo、品牌图案或真实人物头像。

## 验收标准

1. 在 2048px 桌面视口，左栏固定在左、右栏贴住右边缘、中列连续填满中间空间；没有截图中右方的大面积空白。
2. `/hire` 先呈现居中欢迎语和大输入器，输入职位描述后进入同一角色的澄清工作台。
3. 首次澄清卡显示单题选项、编号/单选控件、自定义输入和提交；提交后该项成为 Q/A 历史，下一题自然出现。
4. Agent 收缩文案会引用流程状态（例如“地点已确认，继续确认工作方式”），但不显示模型链式推理。
5. 右侧条件只显示已确认条件及必要的待补充提示，每次回答即时更新版本和内容。
6. 所有核心流程仍为本地模拟；不会提交职位、搜索真实候选人、联系候选人或产生费用。
7. 现有领域测试、界面测试、TypeScript、ESLint、生产构建和浏览器主路径检查通过。

## 非范围

- 不实现截图 3 中的候选人检索、Review Candidates、Contact 或 Interview 实际功能。
- 不接入上传、LinkedIn、职位 URL、支付、试用管理或外部 API；这些入口如出现，只能明确显示为本地模拟。
- 不改变领域问题顺序、持久化格式或后续样本校准领域模型。
