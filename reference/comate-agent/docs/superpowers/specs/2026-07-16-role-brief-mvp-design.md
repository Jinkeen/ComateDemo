# 第一期开发表设计：职位澄清与 Brief 确认

## 一、目标

完成 AI 招聘智能体第一个可运行、可验收的高保真流程：

新建职位 → Agent 澄清职位需求 → 右侧实时生成搜索标准 → 匿名职位 Brief 确认。

页面视觉参照你提供的 Metix 素材，但使用独立品牌、虚构数据和本地模拟状态。

## 二、第一期范围

### 本期要做

- 新建职位入口和本地持久化的职位草稿。
- 固定的桌面三栏招聘工作台。
- 左侧导航、角色列表和不可执行的演示计划卡。
- 中央对话时间线：职位描述、Agent 简短解释、问题卡、回答历史、Brief 确认。
- 地点必答关口，以及按批次出现的澄清问题。
- 单选、自定义文本、上一题、下一题、禁用状态和进度提示。
- 右侧 Progress 与 Search Criteria（搜索标准）面板，并随回答实时更新。
- 公司匿名化选择和最终职位 Brief 确认。
- 刷新后恢复当前进度。
- 每一次回答、返回和状态变化都保存本地审计记录。

### 本期不做

- 候选人样本校准。
- 全量候选人搜索、搜索策略、审批队列和模拟联系。
- 面试日历。
- 真实登录、支付、邮件、候选人数据、文件上传、URL 抓取和外部 API。

## 三、视觉规范

以 D:/招聘助手/metix_report_assets 中的图片为视觉参照，不复制其中的品牌、文案或真实数据。

- 极浅色页面背景，左侧固定浅灰导航。
- 宽屏三栏：窄左导航、居中对话流、窄右侧条件栏。
- 页面标题醒目；对话区保留充足留白。
- 卡片圆角柔和、边框细、阴影弱。
- 紫色用于进度、选中单选项和主要操作。
- 右侧 Search Criteria 使用密集但清晰的条件标签。
- 使用项目自己的名称和图标，不复用 Metix Logo。

## 四、用户流程

1. 招聘者访问 /hire 并输入职位描述。
2. 系统创建本地职位草稿，跳转至 /hire/role/:roleId。
3. Agent 展示原始职位描述，并优先询问工作地点。
4. 招聘者选择地点后，Agent 依次询问工作模式、资历和必备能力。
5. Agent 继续询问学历、行业背景和排除条件。
6. 招聘者输入公司背景；系统区分“真实公司名”和“仅是行业描述”。
7. 招聘者选择是否对候选人显示公司名；若保密，系统生成匿名公司画像。
8. 招聘者填写薪酬、签证与可选面试流程。
9. Agent 生成英文职位 Brief 摘要。
10. 招聘者确认 Brief；第一期流程结束，候选人搜索在界面中保持未开放。

## 五、状态机与跳转规则

| 状态 | 何时进入 | 可执行操作 | 何时离开 |
| --- | --- | --- | --- |
| 职位草稿 | 已输入职位描述 | 提交职位 | 创建本地职位 |
| 地点澄清 | 已识别职位名但地点缺失 | 选择地点 | 地点确认 |
| 分组澄清 | 当前问题组正在进行 | 回答、上一题、下一题、自定义文本 | 当前问题组完成 |
| 公司背景 | 核心招聘条件已完成 | 输入公司信息 | 公司线索已归类 |
| 保密决策 | 已获得公司背景 | 选择公开或保密 | 可见性已确认 |
| 招聘流程信息 | 已确认公司可见性 | 回答或跳过可选问题 | 所有必填项完成 |
| Brief 待确认 | 需求完整 | 确认或返回修改 | Brief 已确认 |
| Brief 已确认 | 已确认 Brief | 仅查看摘要 | 第一期开发表结束 |

硬规则：

- 地点是必填项，未填写不能进入 Brief 待确认。
- 必填题没有有效答案时，下一步按钮必须禁用。
- 第一题不允许返回上一题。
- 每条回答都会保存为审计事件；若允许修改，则保留替换记录。
- 右侧搜索标准从已确认的职位数据生成，不能只依赖页面表单的临时状态。

## 六、模块划分

### 1. 职位领域模块

负责保存职位原文、归一化字段、原始回答、必填项状态和匿名公司画像。它是职位数据的唯一真相来源。

### 2. 澄清工作流模块

负责问题顺序、问题分组、上一题/下一题、校验和允许的状态跳转。

它提供五个清晰动作：

- 回答问题。
- 返回上一题。
- 前进到下一题。
- 跳过可选问题。
- 确认职位 Brief。

### 3. 搜索标准投影模块

将已确认职位数据转换为右侧 Search Criteria 的分组和标签。它只读，不保存表单状态。

### 4. 本地持久化与审计模块

负责保存职位快照、当前工作流状态和追加式审计事件。页面组件不能直接读写浏览器存储。

### 5. 工作台界面模块

负责组合左侧导航、中央对话、澄清问题卡、进度栏与搜索标准面板。它只调用领域动作并渲染查询结果。

## 七、数据模型

### 职位 Brief

- 职位 ID、组织 ID、职位名称、原始职位描述、当前生命周期状态。
- 地点、工作模式、资历、必备能力、学历、行业、排除条件。
- 公司线索、公司阶段、公司领域、公司可见性、匿名公司画像。
- 薪酬、签证政策、面试流程。
- 创建时间、更新时间、搜索标准版本。

### 澄清回答

- 问题 ID、原始回答、归一化回答、是否必填、回答来源、回答时间。

### 审计事件

- 事件 ID、职位 ID、事件类型、前一状态、后一状态、摘要、发生时间。

## 八、错误与空状态

- 空职位描述：主要按钮禁用，并提供可访问的原因说明。
- 自定义答案不合法：显示行内错误，不进入下一状态。
- 已保存数据缺失或损坏：显示可恢复的本地演示错误，并提供新建草稿。
- 浏览器存储不可用：当前会话继续运行，但提示无法持久化。
- 本期不允许产生任何外部网络请求。

## 九、验收标准

1. 用户可以创建一个虚构职位，并完成所有必填澄清问题。
2. 未填写地点时，无法进入最终 Brief。
3. 每个已完成回答都会即时更新右侧搜索标准。
4. 刷新浏览器后，职位、历史回答和当前问题仍能恢复。
5. 选择“公司保密”后，最终摘要展示匿名公司画像。
6. 只有必填字段完整时，才可以确认最终 Brief。
7. 桌面界面在三栏层级、留白、圆角卡片、紫色激活状态和右侧条件密度上与参考素材一致。
8. 浏览器网络面板中不出现候选人搜索、邮件、支付、登录、文件上传或 URL 抓取请求。

## 十、测试策略

| 测试类型 | 验证内容 |
| --- | --- |
| 领域单元测试 | 状态跳转、地点必填、答案归一化、匿名公司画像 |
| 路由集成测试 | 创建职位到确认 Brief，以及刷新恢复 |
| 界面测试 | 禁用状态、上一题/下一题、条件实时更新、保密公司展示 |
| 视觉验收 | 以参考素材核对布局层级；不复制文字、Logo、头像或真实信息 |
